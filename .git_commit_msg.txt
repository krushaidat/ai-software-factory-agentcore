Stop the fake auto-replay; new session triggers real AgentCore

Previously: clicking + New session set ?play=1, which triggered a
client-side scripted-events playback that ran on every page refresh.
The WebSocket pipeline_start was a no-op fire-and-forget. The user
correctly called this out as fake.

Now:
- src/data/corpusContent.ts: representative C/C++ snippets for the 11
  Autoware corpus files (real MISRA-violatable patterns, ~200-400 LOC
  each). Bundled into the frontend.
- SubmitSessionModal: passes (filename, fileContent) to onPick instead
  of (sessionId, filename). Submit reads the snippet from corpusContent.
- WorkspaceShell:
    * Removed startScriptedRun. Replaced with runLive(filename, content)
      that ONLY sends pipeline_start over WebSocket and sets ?running=1
      / ?liveFile=<name>. No URL ?play=1 flag is ever set.
    * Playback hook is now hardcoded to mode='frozen' — never animates,
      so refreshing a session URL never re-plays scripted events.
    * Events resolution: live events win; while ?running=1 with no events
      yet, render an empty state (so PipelinePage can show "Running on
      AgentCore" UI honestly); else show frozen sample events.
    * dataMode=live whenever liveEvents arrive OR an invocation is in
      flight (we are honestly waiting on AgentCore, not faking).
    * On pipeline_completed/failed, drop ?running=1 so refresh doesn't
      re-show the waiting state.
- PipelinePage:
    * Removed the auto-start of the legacy timer-based pipeline
      simulation. THAT was the "dumb pipeline simulates again" bug — a
      setTimeout chain firing on every page load.
    * New isRunningLive + liveFile props. When set, renders a purple
      gradient banner "Running on AgentCore — Supervisor + 6 specialist
      agents are analyzing <file> — real Bedrock Sonnet 4.5 calls. ~3-5
      min."
- PipelineStrip: node sizing fixed — width 132 (was 120), minHeight 92
  (was fixed 70). Stage name wraps to 2 lines instead of being truncated
  by ellipsis at 9px.

End-to-end flow now:
    User clicks "+ New session"
        -> picks a corpus file + clicks Run
        -> WS sends { action: "pipeline_start", payload: { fileId,
                       fileContent, mode: "optB" } }
        -> bridge Lambda receives it, invokes Supervisor Runtime
        -> ~3-5 min later, supervisor result arrives
        -> bridge sends pipeline_completed over WS
        -> frontend dataMode flips DEMO -> Live AgentCore
        -> ?running=1 cleared, results render
